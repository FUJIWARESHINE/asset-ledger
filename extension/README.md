# 资产台账 · 快速录入（Edge / Chrome 扩展）

在平台上浏览时，随时把看到的资产**手动填进弹窗 → 攒成一批 → 一次提交**到自建台账。
不用来回切标签页、不用一个个开台账的新增弹窗。

## 它做什么、不做什么

| | |
|---|---|
| **不做**页面抓取 | 不注入 content script、不读 DOM、不在平台上发任何请求。你在 Cloudflare / GitHub 面板上操作时它完全沉默，不会给账号带来任何额外流量 |
| **不做**平台 API 同步 | 不存 token、不代登录，台账里也没有能进账号的凭据（和台账本身的产品边界一致） |
| 唯一的浏览器读取 | 「取当前页」按钮 —— 只读地址栏里的 URL，和你自己复制粘贴一样，且只在你点的时候读一次 |
| **不自动提交** | 填完先进本地队列，你确认后点「全部导入台账」才真的 POST |

只申请两项权限：`storage`（存队列和配置）、`activeTab`（点按钮时读一次地址）。

## 装

1. 打开 `edge://extensions`（Chrome 是 `chrome://extensions`）
2. 打开左下 / 右上的「开发人员模式」
3. 点「加载解压缩的扩展」，选中本仓库的 `extension/` 目录
4. 建议在工具栏把它固定出来

> 没有上架商店，不需要打包 crx，改完代码点扩展卡片上的刷新按钮即可生效。

## 首次配置

点扩展图标 → 填台账地址（如 `http://192.168.1.100:8787`）→ 有 `APP_PASSWORD` 就一并填上 → **保存并连接**。

地址在扩展默认授权范围内（`localhost` / `127.0.0.1` / `192.168.*` / `10.*`），直接连。

如果要走**域名或别的网段**（比如反代到 `assets.example.com`），`保存并连接` 会提示未授权 ——
这时点「打开设置页授权」，在那边的标签页里点一次「授权并保存」，浏览器会弹一次确认框。

> 为什么不在弹窗里弹授权框：MV3 的 `permissions.request` 会抢焦点，弹窗一失焦就被关闭，
> 授权流程会断掉。所以授权只在设置页做。

## 日常用法

```
点图标 → 选账号 → 填名称（+ 可选：链接、类别、到期）
       → 「加入待导入」（回车也行，名称/链接框里直接回车）
       → 继续浏览下一个资产，重复……
       → 点顶部徽章展开队列 → 「全部导入台账」
```

- **归属账号**会记住你上一次选的；连续录同一账号下的东西不用反复选
- **类别**会保留（连续录域名很顺），费用 / 周期 / 币种在入队后复位，避免 USD 悄悄带到下一条
- **到期日**有 `+1 年 / +1 月 / +30 天 / 清空` 快捷键，跨月不会算错（1 月 31 日 +1 月 → 2 月底）
- **选到「域名 / 二级域名」时「更多字段」自动展开**，方便填申请商 + 申请账号（双维度归属）
- **账号不存在**就点下拉右边的 `＋` 就地建一个，建完自动选中
- **重复检测**默认开启：导入前拉一次台账全量，account + 名称重复的直接跳过并标出来。
  同名但不同账号不算重复

## 导入结果

导入后逐条给结果：`已入库 #12` / `台账里已有同名，跳过` / `失败：<原因>`。

失败的**留在队列里**，不会丢。遇到密码或连接类错误会立即停下（后面每条都会失败，没必要刷一屏）。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 标题旁红点 + 「连不上台账」 | 地址错、不在同一网段、容器没起，或该地址未被授权（去设置页授权） |
| 「访问密码不对」 | `APP_PASSWORD` 填错，或台账设了密码但扩展里空着 |
| 「归属账号不存在」 | 台账那边把账号删了。刷新弹窗（重开一次）会重新拉账号列表 |
| 「这个标签页没有可用地址」 | 当前页不是 http/https（比如 `edge://` 页面），手动粘贴即可 |
| 队列里的东西没了 | 队列存在扩展本地存储，卸载扩展 / 清浏览器数据会一起没。重要内容及时导入 |

## 字段对应

扩展提交的就是台账 `POST /api/assets` 的原生字段，没有中间格式：
`name / category / account_id / url / environment / status / expires_at / auto_renew /
cost / currency / cycle / credential_hint / tags / notes / provider / provider_account`。

平台和账号两个字段**不在扩展里填** —— 由 `account_id` 在服务端反推，保证不会两处不一致。

## 后端要求

**不需要改后端。** 用的是已发布的 `GET /api/meta`、`GET /api/accounts`、`GET /api/assets`、
`POST /api/assets`、`POST /api/accounts`，老版本台账（v0.1.0 起）都能直接连。

启用密码时扩展自动带 `X-App-Password` 请求头。

## 开发

```
extension/
├── manifest.json   MV3 声明（局域网 host_permissions + optional 兜底）
├── common.js       存储 / API / 地址规范化 / 权限探测（popup 与设置页共用）
├── popup.html/.css/.js     主弹窗
├── options.html/.js        设置页（授权必须在这里做）
└── icons/          icon16/32/48/128，由 tools/make_icons.py 纯标准库生成
```

`common.js` 在 `chrome` 缺失时会自动降级到 `localStorage`，
所以直接拿浏览器打开 `popup.html` 也能调 UI（只是没有标签页 API）。

源码里已加了几处针对扩展首次加载的容错：`chrome.storage` / `chrome.permissions`
在扩展刚被载入时可能长时间不 resolve，`withTimeout` 兜住了，界面不会白屏。
